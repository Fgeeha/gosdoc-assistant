# 0007. Базовые образы Astra Linux / РЕД ОС

**Контекст.** Образы должны собираться из отечественных реестров, приоритет у
сертифицированной ФСТЭК ОС.

**Решение.** Один `deploy/docker/Dockerfile`, аргумент `BASE_IMAGE`:

- `registry.astralinux.ru/astra/ubi18` — по умолчанию (apt);
- `registry.red-soft.ru/ubi8/ubi` — РЕД ОС (dnf).

Пакеты ОС ставит `deploy/docker/os-packages.sh`: он определяет менеджер пакетов
и сопоставляет имена (например, `tesseract-ocr-rus` / `tesseract-langpack-rus`).
Если пакета нет, сборка падает с явным сообщением, без молчаливой подмены
образа. Python-зависимости ставит uv (сам uv — из зеркала PyPI, `PIP_INDEX_URL`).
Фронтенд собирается в стадии с Node.js из пакетов ОС, статику отдаёт nginx из
пакетов той же ОС. `python:3.11-slim` используется только в
`docker-compose.dev.yml`.

**Последствия / проверить.** Наличие пакетов в репозиториях Astra 1.8 и РЕД ОС 8
не проверено: реестры недоступны с машины разработки (Astra — таймаут,
РЕД ОС — нужен корневой сертификат «Russian Trusted Root CA»). Первая сборка в
контуре ЦИТ — контрольная. Если Node.js в репозитории ОС старше 18, сборку
фронтенда нужно перенести в CI-артефакт (сборка `npm ci && npm run build` на
раннере) и копировать готовую статику в образ.
