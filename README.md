# ГосДок Ассистент

Помощник для сотрудников государственной службы: проверка документов по
нормативной базе, подготовка служебных писем, перенос данных между таблицами.
Работает полностью в закрытом контуре: модель, поиск и хранилище — локальные,
обращений к внешним адресам нет.

Все результаты, подготовленные автоматически, — черновики и требуют проверки
сотрудником.

## Быстрый старт

Нужны Docker с Compose v2 и `make`.

```sh
make up-local        # при первом запуске создаст .env из .env.example
```

Откройте http://localhost:8080. Логин `admin`, пароль — `GOSDOC_ADMIN_PASSWORD`
из `.env`; при первом входе его нужно сменить.

Поднимаются PostgreSQL, Redis, RabbitMQ, Elasticsearch, ChromaDB, SeaweedFS
(S3), заглушка модели и само приложение. Сервисы находятся во внутренней сети
Docker без выхода наружу; опубликован только порт веб-интерфейса.

## Разработка

```sh
make install         # зависимости (uv, npm)
make check           # ruff, mypy, tsc и все тесты
make test-unit       # быстрые тесты без Docker
make help            # все цели
```

Интеграционные тесты поднимают PostgreSQL и SeaweedFS через testcontainers.
Тесты не могут ходить во внешнюю сеть (`pytest-socket`): разрешены только
локальные адреса.

## Конфигурация

Все параметры задаются переменными окружения, полный список с описанием — в
`backend/gosdoc/core/config.py`. Основные:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL`, `REDIS_URL`, `RABBITMQ_URL` | подключение к сервисам |
| `STORAGE_BACKEND` | `s3` (SeaweedFS и др.), `postgres` или `local` |
| `S3_ENDPOINT_URL`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` | S3-хранилище |
| `FILE_RETENTION_DAYS` | срок хранения загруженных файлов (30) |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_MAX_CONTEXT` | модель (OpenAI-совместимый API) |
| `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_MODEL` | эмбеддинги, если сервис отдельный |
| `AUTH_PROVIDER` | `local` или `ldap` |
| `CA_BUNDLE` | корневой сертификат для TLS к сервисам `*.fgau.local` |

## Модуль «Перенос данных между таблицами»

Раздел «Таблицы» в интерфейсе:

1. Загрузите одну или несколько исходных таблиц и целевой шаблон (первая
   строка — заголовки; строка-пример под ними задаёт оформление).
2. «Предложить маппинг»: колонки сопоставляются по названиям и виду данных;
   для неуверенных — моделью, которой передаются только названия колонок и
   форма значений (`Аааааа А.А.`), без данных. Предложение — черновик.
3. Проверьте маппинг, при необходимости поправьте, посмотрите предпросмотр.
4. «Перенести»: на каждый файл — фоновая задача. Результат — XLSX в
   оформлении шаблона, отчёт — XLSX со всеми не перенесёнными строками и
   причиной. Всегда `строк в источнике = перенесено + отфильтровано + отклонено`.

Маппинг можно сохранить как шаблон (личный или общий для организации); с
ним хранится только строка заголовков шаблона. Примеры — `tests/fixtures/tables`
(пересборка: `uv run python tests/fixtures/tables/build_fixtures.py`).

## Модуль «Подготовка писем»

1. Администратор системы в разделе «Организация» задаёт наименование и
   справочные данные для бланка, подписанта по умолчанию, маску исходящего
   номера (регулярное выражение) и переносы выходных. При необходимости
   загружает свой бланк — DOCX-шаблон docxtpl с переменными из
   `gosdoc.letters.gost.CONTEXT_VARS` (пример — `tests/fixtures/letters/blank.docx`).
   Без загруженного бланка используется встроенный по ГОСТ Р 7.0.97-2016.
2. Исполнитель в разделе «Письма» выбирает тип, загружает входящее (DOCX,
   PDF с текстом, TXT), описывает задачу — модель готовит **черновик** только
   смысловых блоков; реквизиты подставляет система.
3. Текст правится в интерфейсе, каждое сохранение — новая версия. Справа —
   срок ответа (обращения граждан: 30 дней с регистрации, продление ещё на 30),
   соответствие номера маске и замечания по стилю.
4. DOCX формируется сразу, PDF — воркером через LibreOffice.
5. Руководитель того же подразделения утверждает письмо (снимает отметку
   «черновик»); после этого письмо не редактируется.

## Модуль «Проверка документов»

1. **Нормативная база** (роль «Администратор нормативной базы»; общие акты —
   «Администратор системы»): загрузка DOCX/HTML/PDF по одному, пакетом или
   zip. Вид, номер, дата и редакция («в ред. от …») определяются по заголовку
   акта; повторная загрузка — новая редакция, границы действия редакций
   считаются автоматически. Отмену акта отмечают вручную («статус»). Все
   изменения — в журнале. Индексация (PostgreSQL + Elasticsearch с русской
   морфологией + векторный индекс) идёт в фоне.
2. **Проверка** (раздел «Проверка»): DOCX, ODT, PDF, сканы PDF (Tesseract),
   TXT. Ссылки на НПА проверяются по базе без модели: акт утратил силу,
   ссылка на устаревшую редакцию (и изменился ли текст указанной статьи),
   неверная дата, нет такой статьи. Содержание абзацев сверяется с найденными
   нормами (гибридный поиск + RRF); замечание попадает в отчёт **только если
   цитата дословно найдена** в тексте нормы — иначе отбрасывается.
3. Результат: отчёт в интерфейсе и DOCX, исходный документ с примечаниями
   Word (предлагаемая правка — в тексте примечания, ADR-0010). Каждое
   замечание сотрудник может отметить «верно/неверно».

Тестовая база — `tests/fixtures/npa` (59-ФЗ в двух редакциях, 152-ФЗ,
утративший силу 24-ФЗ) и проверяемый документ `checked-document.docx`.
Это **сокращённые выдержки** для тестов: номера статей настоящие,
формулировки упрощены. Для работы загружайте официальные тексты.

## Развёртывание в Kubernetes

1. Соберите и опубликуйте образы: `make images BASE_IMAGE=... IMAGE_PREFIX=<реестр>/gosdoc/gosdoc`
   (в CI — этап `build`).
2. Создайте Secret с ключами `DATABASE_URL`, `RABBITMQ_URL`, `S3_ACCESS_KEY`,
   `S3_SECRET_KEY`, `LLM_API_KEY`, `SERVICE_TOKEN` (32+ символов),
   `GOSDOC_ADMIN_PASSWORD` и ConfigMap с корневым CA.
3. `helm upgrade --install gosdoc deploy/helm/gosdoc -f values.yaml`
   (пример — `deploy/helm/gosdoc/values-example.yaml`).
4. Выложите `airflow/dags/*.py` в заказанный Airflow, задайте Variables
   `gosdoc_api_url`, `gosdoc_service_token`, `gosdoc_ca_bundle`
   (и `gosdoc_evidently_url`, `gosdoc_evidently_project`).
5. Логи — см. `deploy/monitoring/README.md`.
