# ГосДок Ассистент

[![CI](https://github.com/Fgeeha/gosdoc-assistant/actions/workflows/ci.yml/badge.svg?branch=Master)](https://github.com/Fgeeha/gosdoc-assistant/actions/workflows/ci.yml)

Рабочее место сотрудника государственной службы, которое берёт на себя
рутину с документами: сверяет документ с действующими нормативными актами,
готовит черновик служебного письма по ГОСТ и переносит данные из одной
таблицы в другую без потерь.

Всё работает **в закрытом контуре**: языковая модель, поиск и хранилище
файлов разворачиваются внутри организации, персональные данные за периметр
не уходят (152-ФЗ), обращений к внешним адресам нет.

> Всё, что подготовлено автоматически, — черновик. Решение и ответственность
> остаются за сотрудником.

## Знакомство за пять минут

### Что умеет

| Раздел | Задача сотрудника | Что делает система |
|---|---|---|
| **Проверка** | «Не сослались ли мы на отменённый закон?» | Находит в документе ссылки на НПА и сверяет их с нормативной базой: акт утратил силу, устаревшая редакция, неверная дата, нет такой статьи. Сверяет содержание с нормами и к каждому замечанию прикладывает **дословную цитату** — замечание без подтверждающей цитаты не показывается. Возвращает ваш DOCX с примечаниями Word на полях. Понимает DOCX, ODT, PDF, сканы (OCR), TXT. |
| **Письма** | «Нужно ответить на обращение гражданина» | Готовит черновик ответа на обращение, запроса или сопроводительного письма. Реквизиты расставляет по ГОСТ Р 7.0.97-2016, считает срок ответа по 59-ФЗ с учётом выходных и праздников, проверяет стиль и маску исходящего номера. Хранит версии, отдаёт DOCX и PDF; письмо утверждает руководитель. |
| **Таблицы** | «Перенести реестр из выгрузки в форму отчёта» | Сопоставляет колонки источника и шаблона, преобразует значения (ФИО, даты, суммы, справочники), проверяет ИНН, СНИЛС, ОГРН по контрольным суммам. Ни одна строка не теряется: каждая либо в результате, либо в отчёте с причиной. Форматы XLSX, XLS, CSV, ODS. |

### Как это выглядит на примере

В репозитории есть готовые примеры — с ними удобно посмотреть систему в деле:

- `tests/fixtures/npa/checked-document.docx` — документ со ссылками на
  отменённый 24-ФЗ и старую редакцию 59-ФЗ. Проверка находит обе ошибки, а с
  подключённой моделью — ещё и неверный срок «60 дней» с цитатой нормы
  «30 дней».
- `tests/fixtures/letters/appeal.docx` — обращение гражданина для черновика
  ответа.
- `tests/fixtures/tables/source.xlsx` → `template.xlsx` — 11 строк:
  4 переносятся, 2 отфильтровываются, 5 отклоняются с причиной (неверный ИНН,
  пустое обязательное поле и т. п.).

### Как устроено

```
Браузер ── nginx ── API (FastAPI) ── PostgreSQL     пользователи, документы, аудит
                     │               Redis          сессии
                     │               SeaweedFS (S3) файлы, срок хранения 30 дней
                     └─ RabbitMQ ── воркеры         OCR, индексация, PDF, перенос таблиц
                                     │
                                     ├─ Elasticsearch + векторный индекс   поиск по НПА
                                     └─ модель (OpenAI-совместимый API в контуре)
```

Модульный монолит: общее ядро (вход, роли, аудит, файлы) и три модуля по
разделам. Каждая организация видит только свои данные. Подробно —
[архитектура](docs/architecture.md) и [решения (ADR)](docs/adr).

## Быстрый старт

Нужны Docker с Compose v2 и `make`.

```sh
git clone git@github.com:Fgeeha/gosdoc-assistant.git && cd gosdoc-assistant
make up-local        # при первом запуске создаст .env из .env.example
```

Откройте http://localhost:8080. Логин `admin`, пароль — `GOSDOC_ADMIN_PASSWORD`
из `.env`; при первом входе его нужно сменить.

Первые шаги:

1. «Нормативная база» → загрузите акты из `tests/fixtures/npa`.
2. «Проверка» → загрузите `checked-document.docx` и откройте замечания.
3. «Таблицы» → загрузите `source.xlsx` и `template.xlsx`, нажмите
   «Предложить маппинг», затем «Перенести».

Поднимаются PostgreSQL, Redis, RabbitMQ, Elasticsearch, ChromaDB, SeaweedFS,
заглушка модели и само приложение. Сервисы находятся во внутренней сети
Docker; наружу опубликован только порт веб-интерфейса. С заглушкой модели
черновики писем получаются шаблоном с пометками [уточнить] — для осмысленного
текста укажите в `.env` адрес своей модели (`LLM_BASE_URL`).

## Разработка

```sh
make install         # зависимости (uv, npm)
make check           # ruff, mypy, tsc и все тесты
make test-unit       # быстрые тесты без Docker
make help            # все цели
```

Интеграционные тесты поднимают PostgreSQL и SeaweedFS через testcontainers.
Тесты не могут ходить во внешнюю сеть (`pytest-socket`): разрешены только
локальные адреса.

Каждый push и pull request проверяется в GitHub Actions
(`.github/workflows/ci.yml`): линтеры, тесты, Helm-чарт и сборка образов.
Конвейер для контура (сборка на Astra Linux / РЕД ОС, сканирование, выкатка) —
`.gitflic-ci.yml`.

```
backend/gosdoc/   API и доменная логика: core — ядро; tables, letters, docs_check — модули
backend/alembic/  миграции БД
workers/          фоновые задачи dramatiq
rag/              нарезка НПА и гибридный поиск
frontend/         React + TypeScript + Ant Design
airflow/dags/     регламентные задачи
deploy/           Dockerfile, docker-compose.dev.yml, заглушка модели, Helm, мониторинг
docs/             архитектура, ADR, руководства
tests/            unit, integration, fixtures
```

## Конфигурация

Все параметры задаются переменными окружения, полный список с описанием — в
`backend/gosdoc/core/config.py`. Основные:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL`, `REDIS_URL`, `RABBITMQ_URL` | подключение к сервисам |
| `STORAGE_BACKEND` | `s3` (SeaweedFS и др.), `postgres` или `local` |
| `S3_ENDPOINT_URL`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` | S3-хранилище |
| `FILE_RETENTION_DAYS` | срок хранения загруженных файлов (30) |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_MAX_CONTEXT` | модель (OpenAI-совместимый API) |
| `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_MODEL` | эмбеддинги, если сервис отдельный |
| `AUTH_PROVIDER` | `local` или `ldap` |
| `CA_BUNDLE` | корневой сертификат для TLS к сервисам `*.fgau.local` |

## Развёртывание в Kubernetes

1. Соберите и опубликуйте образы: `make images BASE_IMAGE=... IMAGE_PREFIX=<реестр>/gosdoc/gosdoc`
   (в контуре — этап `build` в `.gitflic-ci.yml`).
2. Создайте Secret с ключами `DATABASE_URL`, `RABBITMQ_URL`, `S3_ACCESS_KEY`,
   `S3_SECRET_KEY`, `LLM_API_KEY`, `SERVICE_TOKEN` (32+ символов),
   `GOSDOC_ADMIN_PASSWORD` и ConfigMap с корневым CA.
3. `helm upgrade --install gosdoc deploy/helm/gosdoc -f values.yaml`
   (пример — `deploy/helm/gosdoc/values-example.yaml`).
4. Выложите `airflow/dags/*.py` в Airflow, задайте Variables
   `gosdoc_api_url`, `gosdoc_service_token`, `gosdoc_ca_bundle`
   (и `gosdoc_evidently_url`, `gosdoc_evidently_project`).
5. Логи — см. `deploy/monitoring/README.md`.

Подробно — в [руководстве администратора](docs/guides/admin.md).
